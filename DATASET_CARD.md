# ZOMBIE MODE: Fog of Containment dataset

## Origin, rights, and intended use

Creator-owned fictional synthetic cities generated by `build.py` on 2026-10-22. No upstream dataset, real measurements, persons, locations, infection cases, or human subjects are used. This pack is released under CC0 1.0; software scripts are MIT licensed. It is intended only for benchmark research in inference and ordered combinatorial decision making. It is not a public-health model. The canonical participant-safe source release for v1.0.3 is https://github.com/anjalikhatri019-hub/zombie-mode-fog-containment-dataset/releases/tag/v1.0.3. The organizer-only answer table, generator, and seed-index manifest are outside that public source release.

## Exact participant archive inventory

- `train.csv`: 384 labeled cities, one row per city.
- `test.csv`: 128 held-out cities, no realized payoff or answer columns.
- `sample_submission.csv`: one valid policy per held-out city.
- `sensors/<case_id>.npy`: 512 NumPy `.npy` arrays, each shape `(8,64,64,8)`, little-endian uint16; axes are observation time, y, x, and channel. Values range from 0 to 65535.
- `DATASET_CARD.md` and `task_prompt.txt`: this card and the full solver contract.

The platform organizer upload ZIP contains the 517 members above **and** `answers_private.csv` (518 members total). That CSV stores private test payoff values with columns `case_id,base_json,pair_json,oracle,random_mean`. The Prepare entrypoint writes it to `private_dir`. It writes the 517 listed participant files to `public_dir`; the separately hosted public source ZIP contains those same 517 files. The creator generator and family/split manifest are retained only in the local creator kit.

## Columns and units

`case_id` is an opaque row key, not a feature. `sensor_path` is an array address. `hubs_json` is a JSON list of twelve `[x,y]` integer grid points. `capacity_json` is a JSON list of twelve positive unitless crew multipliers in the corresponding local hub order. `base_json` is twelve realized single-hub benefits in synthetic utility units. `pair_json` is a 12×12 directed matrix of shared-crew costs in the same units; diagonal entries are zero. `oracle` is the maximum realized value over 12P4 ordered policies. `random_mean` is the arithmetic mean of those policy values, not a probability or a normalized score. `oracle_policy` is one maximizing four-index policy. The sample submission has `case_id` and JSON `policy` columns.

Sensor channels 0–7 are respectively noisy observed zombie presence, mixed thermal/population response, horizontally displaced presence, vertically displaced presence, noisy population, noisy road density, noisy presence-population interaction, and nuisance beacon interference. All are simulation-specific normalized sensor units, quantized after clipping. The eighth frame is the last pre-intervention observation. Target payoffs use a hidden burden field seven frame intervals after that observation and a smooth response footprint around each hub. Motion, hotspots, noise, crew capacities, hub order, and interference vary by city. The generated response field and payoff matrix are private for test cities.

## Split and limitations

Sixteen mechanism families vary hotspot count, nuisance phase, and sensor-noise regime. Families 0–11 make training cases; families 12–15 make held-out cases. Each family contributes 32 cases. The family number and generator index are never a participant feature. The split tests moderate mechanism transfer within one invented simulator; it does not establish transfer to real outbreaks. Synthetic signal structure, simplified response footprints, and absent social, ethical, and epidemiological factors are major coverage gaps. The public source page is a provenance and reproducibility mirror; the platform supplies prepared train/test/sample files to participants.
